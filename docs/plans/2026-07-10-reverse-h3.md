# Reverse Geocoding: H3 Country Router + Exact Containment

Date: 2026-07-10
Branch: `reverse-h3-country-router`
Status: Prototype + improved bbox routing shipped, H3 design ready

## Summary

Replace bbox-only reverse with more accurate pipeline:

1. **H3 country router** (res 2-3) for precise lat/lon → country shard without world-spanning bbox false positives
2. **Exact polygon containment** via optional simplified WKB column + point-in-polygon
3. **Materialized parent hierarchy** via parent pointers

Fixes Tokyo regression (35.68,139.69 → JP) and dateline/irregular boundaries.

## Current Architecture

- `select_reverse_shards()` in stac.rs: iterates reverse-collection bboxes, containment via distance_to_bbox==0, if exactly 1 contains use it else fallback CF-IPCountry → HEAD
- `Database::reverse_geocode()`: R*Tree prefilter, window keeps 8 smallest per subtype, dedup gers_id, priority subtype priority over area, centroid haversine tie-break factor 4x, hierarchy inferred smallest per subtype

Issues F5/F14:
- Country bboxes union of components → RU/US with parts both sides dateline → [-180,180] width → contains every lon → forces IP fallback
- distance_to_bbox didn't handle min_lon > max_lon (Fiji)
- Overlapping US/CA ambiguous
- No exact polygon
- Hierarchy inferred not materialized

PR #43 fixed subtype priority; this PR builds on it.

## H3 vs S2 Tradeoffs

| Aspect | H3 (hex) | S2 (quad) |
|---|---|---|
| Cell shape | Hex 6 neighbors uniform | Quad 4 children Hilbert |
| Projection | Icosahedron area-preserving-ish | Cube better near poles |
| Wasm | h3 C-binding fails wasm, h3o pure Rust works | s2 pure Rust works but larger |
| Res levels | 0:122 cells 1107km, 1:842, 2:5882 avg158km, 3:41162 avg60km, 4:288k avg22km | L6 ~1°, L10 ~0.1°, L12 ~0.02° |
| Storage | 64-bit int | 64-bit cell ID |
| Fit | Good: res2 ~5882 cells global, country few to hundreds, boundary ~20% | Similar hex better adjacency |

Choice: H3 res2-3.

- res2 5882 cells avg 250k km2 country-scale
- res3 41162 cells avg 60km edge ~10k km2 more precise
- Boundary cells need polygon exact check; interior direct mapping.

Wasm: use h3o crate pure Rust; Python build uses h3-py C fine.

Why not S2: S2 spherical-acc accurate vs H3 planar-ish but for country level negligible. Hex uniform adjacency better for irregular borders.

## Build Pipeline Design

### Phase 1: Country H3 index (Python offline)

Script `scripts/build_country_h3_index.py`:

1. Input division-area parquet filtered subtype=country
2. For each country load WKB via shapely, merge unary_union, make_valid, simplify optional
3. Polyfill at res2/3: h3.geo_to_cells(geojson,res)
4. Build inverse cell→[countries]; cells single country interior, multiple boundary
5. For boundary store list candidates + simplified country polygons clipped to cell bbox +10% padding
6. Current output is a sizing prototype only: center-point polyfill does not prove a cell is wholly interior and misses some coast/border intersections. Before routing, classify candidate cells by cell-polygon intersection and send every non-covered cell through exact containment. Proposed output SQLite country_h3.db: h3_cells(cell PK,country,is_boundary)+boundary_polys(cell,country,wkb) or JSON {resolution,cells:{h3:country},boundary:{h3:{candidates:[],polys:{country:hex}}}}. Size estimate: res2 5882 center cells <100KB JSON; the corrected boundary set must be remeasured.

### Phase 2: Reverse shards with WKB

Modify build_shards.py:

- Schema wkb BLOB optional
- Query division_area join to get simplified geometry per division: ST_SimplifyPreserveTopology(geom,0.0005)
- For antimeridian keep split rows each with its own simplified WKB component
- Store simplified WKB binary
- Size estimate Overture area 20k rows ×1-2KB=20-40MB total fleet vs current 10MB acceptable per shard +0-2MB under 128MB limit
- Optimization store WKB only for admin levels or where bbox area >> polygon area or centroid not inside

### Phase 3: Worker integration

- Load country_h3.db into isolate cache (like RouterDb)
- select_reverse_shards: h3.latlng_to_cell(lat,lon,res=2) → lookup, interior → return country shard, boundary → fetch candidate polys point-in-poly exact (geo crate or ray-cast) return matching, miss/no H3 → fallback improved bbox smallest-area → CF country → HEAD
- Database::reverse_geocode exact containment using shard wkb as implemented

### Phase 4: Materialized Parent Hierarchy

Current hierarchy inferred smallest per subtype. Better use Overture parent_id or admin hierarchy.

- In DuckDB build join division → division_area parent chain via country,region or parent_gers_id if exists
- Store parent_gers_id in divisions_reverse
- Then hierarchy walk parent pointers
- Size extra 16-byte UUID per row ~300KB/shard

Future parent materialization deprecates area-based confidence → containment confidence (high if inside exact poly, medium if near edge)
