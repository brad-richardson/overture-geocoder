# Before/after benchmark — 2026-07-02 ranking + pipeline overhaul

Date: 2026-07-02
Live version measured: `2026-07-02.1` (5.1 MB HEAD, 0.65 wiki bar, alt-name
ladder, comma truncation, NormalizedQuery hoist, in-SQL legacy boost).
Baseline: `benchmarks/2026-06-11-vs-nominatim-photon.json` (June 11 data +
pre-overhaul ranking).

Raw data: `2026-07-02-vs-nominatim-photon.json` (full-query, 50 queries),
`2026-07-02-typeahead.json` (progressive-prefix, 16 cases).

## Headline

- **Correct-location rate up, wrong-city-with-right-name eliminated** on the
  15-city global set: within-50km went 10/15 → 12/15. June returned Rome GA
  for "Rome" (8,107 km off), a US "Cairo" (2,569 km), a US "Moscow"
  (8,375 km); all three now return the real city (≤1.5 km).
- **Median full-query latency 77 ms → 61 ms** (same 15 queries; 60 ms median
  over the full 50-query US+global set, p95 74 ms). NormalizedQuery hoist +
  always-in-SQL legacy boost.
- **Type-ahead: median 3 keystrokes to top-1 vs Photon's 4**, at 56 ms p50 vs
  Photon's 473 ms — competitive accuracy at ~8x lower latency.

## Real defects found by this benchmark

1. **"mexico city" → Albuquerque, NM at rank 1** (CDMX at rank 2). Root
   cause: `build_shards.py` flattens all name variants into an unordered,
   deduplicated token bag (`search_name` for CDMX is
   `"mx. federal cd. d.f. distrito city mexico cdmx district méxico de
   ciudad"`), so the phrase "mexico city" can never hit the exact/prefix
   rungs of the match ladder — it degrades to partial quality, and a
   same-country result with incidental token hits ("New Mexico" context +
   proximity) wins. Fix direction: store alt names as distinct strings (or
   at least preserve adjacency for common exonyms) so `alt_name_quality`
   can phrase-match. Not attempted today — it is a shard schema change.
2. **Overture source data contains near-duplicate divisions**: 11 name+type
   pairs appear twice with distinct GERS IDs in HEAD alone (e.g. Ciudad de
   México twice, importance 0.671 vs 0.891). Harmless for correctness but
   wastes result slots; could dedup by (name, country, ~distance) at build
   time.

## HEAD shard, post-overhaul

11,004 records / 5.1 MB (219 countries, 3,917 regions, 6,868 localities with
wiki importance ≥ 0.65). Down from 28.9 MB on `.0` (bad single 0.5 bar) and
8.4 MB in June — the 0.65 bar is stricter than June's criteria while keeping
famous-small places searchable globally (Gettysburg, Reykjavík, Zermatt-class
entries live in HEAD or resolve through country shards).
